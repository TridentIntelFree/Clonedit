# JBH-88 agent connector

One file — [`jbh88-agent.mjs`](jbh88-agent.mjs) — that lets an AI agent work
in the JBH-88 window a person has open, at the same time as them.

**You do not need the source code.** Do not clone the repository. Download
the one file:

    https://tridentintelfree.github.io/Clonedit/agent/jbh88-agent.mjs

## Setting it up

1. Have **Node.js 18 or newer** (nodejs.org).
2. Add it to the agent's MCP config, with the real path to the file:

   ```json
   {"mcpServers":{"jbh88":{"command":"node","args":["C:/Users/you/Downloads/jbh88-agent.mjs"]}}}
   ```

   Claude Desktop: Settings → Developer → Edit Config, then restart it.
   Claude Code: `claude mcp add jbh88 -- node /path/to/jbh88-agent.mjs`.
3. Ask the agent to **connect to JBH-88**. Its first call, `jbh_connect`,
   finds the open window (or opens one) and both sides show the same
   four-letter code. If the browser asks to let the site reach apps on this
   device, press Allow. After the first time it reconnects by itself.

Or, in the app: **SONG → CONNECT AN AGENT ON THIS COMPUTER**.

## What it can and cannot reach

| | |
| --- | --- |
| The JBH-88 window | Everything: sounds, pads, patterns, notes, mix, transport, every analyser. The person sees each change land and can keep working. |
| Files | **One folder only**: `~/Music/JBH-88` (or `~/JBH-88`; `JBH_TRACKS` moves it). Tools take a file *name*, never a path. |
| The network | It listens on `127.0.0.1` only. Only the JBH-88 page may connect; a page from any other site is refused by its Origin, and a page with no origin needs the token in the link the connector hands out. |
| Anything else on the computer | Nothing. It does not read the repository, the home folder or any other file. |

Calls that replace the open session (`jbh_clear`, `jbh_load_track`) make the
app take a checkpoint first, so the person's work is one tap away in
SONG → REWIND.

## Delivering a song

`jbh_save_track {name:"first light"}` bounces the song and writes

- `first light.mp3` — to listen to and share in any chat
- `first light.wav` — full quality
- `first light.json` — the whole session; opens in JBH-88 with SONG → LOAD .JSON

and returns each file's path and a `file://` link (as MCP `resource_link`s
for clients that support them, and as resources the client can list). With
`inline:true` the MP3 also comes back as audio in the reply when it is under
8 MB. `jbh_list_tracks` and `jbh_load_track` see the same folder and nothing
else.

## Settings

| Variable | Default | |
| --- | --- | --- |
| `JBH_TRACKS` | `~/Music/JBH-88` | the one folder files go to |
| `JBH_SITE` | the published app | where `jbh_connect` opens the app |
| `JBH_PORT` | `47888` | first port tried; it takes the first free of eight |
| `JBH_NO_OPEN` | | `1` = never open a browser, only return the link |
| `JBH_ORIGINS` | | extra page origins to accept, comma-separated |

Several agents can be connected at once: each connector takes its own port
and the app connects to all of them.

## For developers of JBH-88

This file is generated by `node scripts/build-agent.mjs` from
`agent/src/connector.mjs` and `mcp/tools.mjs` (the tool list it shares with
`mcp/server.mjs`, which runs its own hidden copy of the app for work inside
a checkout). It bundles lamejs (LGPL-3.0) unminified for the MP3 encoding.
